# Power BI Dashboard Guide — Orobic Precision Parts KPI Dashboard

Step-by-step instructions for building the interactive dashboard from the five
processed CSV tables.  All DAX measures are in `dax_formulas.md`.

---

## Prerequisites

- Power BI Desktop (latest version — free download from Microsoft)
- Five processed CSV files in `data/processed/` (generated by `etl_pipeline.py`)
- No Power BI Pro licence required for local development

---

## Step 1 — Load the data

1. Open Power BI Desktop → **Get data → Text/CSV**
2. Load all five files:

   | File | Load as |
   |---|---|
   | `kpi_daily.csv` | kpi_daily |
   | `kpi_monthly.csv` | kpi_monthly |
   | `machine_performance.csv` | machine_performance |
   | `downtime_analysis.csv` | downtime_analysis |
   | `defect_analysis.csv` | defect_analysis |

3. In Power Query Editor, verify column types:
   - `Date` in `kpi_daily` → **Date** type (`dd/mm/yyyy` locale)
   - All `Year`, `Month_Num`, `Process_Step` → **Whole number**
   - All `Avg_OEE`, `Avg_Availability`, etc. → **Decimal number**
   - `Machine`, `Downtime_Reason`, `Defect_Type` → **Text**
4. Click **Close & Apply**

---

## Step 2 — Create the Date table

In the **Data** view, create a new table with this DAX (from `dax_formulas.md`):

```dax
DateTable =
ADDCOLUMNS(
    CALENDAR( DATE(2023,1,1), DATE(2024,12,31) ),
    "Year",       YEAR([Date]),
    "Month_Num",  MONTH([Date]),
    "Month_Name", FORMAT([Date], "MMM"),
    "Quarter",    "Q" & ROUNDUP( MONTH([Date]) / 3, 0),
    "Week",       WEEKNUM([Date], 2)
)
```

Then: **Table tools → Mark as date table → Date column = Date**

---

## Step 3 — Build the data model (relationships)

Go to **Model view** and create the following relationships:

| From | To | Cardinality | Active |
|---|---|---|---|
| `kpi_daily[Date]` | `DateTable[Date]` | Many-to-one | Yes |
| `kpi_daily[Machine] + [Year] + [Month_Num]` | `kpi_monthly` (same columns) | Many-to-one | Yes |
| `kpi_monthly[Machine] + [Year]` | `machine_performance` (same) | Many-to-one | Yes |
| `downtime_analysis[Machine] + [Year] + [Month_Num]` | `kpi_monthly` | Many-to-one | Yes |
| `defect_analysis[Machine] + [Year] + [Month_Num]` | `kpi_monthly` | Many-to-one | Yes |

> **Tip:** Composite key relationships (multiple columns) are created via
> **Manage relationships → New → select matching columns**.

---

## Step 4 — Create all DAX measures

Create a dedicated **Measures table** (blank table named `Measures`).
Then add every measure from `dax_formulas.md`.  Recommended grouping:

| Measure group | Measures |
|---|---|
| Core KPIs | Plant OEE, OEE Weighted, Avg Availability, Avg Performance, Avg Quality, Scrap Rate, Total Downtime Hours |
| vs Benchmark | OEE Gap to World-Class, OEE Status |
| Time intelligence | OEE MoM Change, OEE YTD, OEE Rolling 3M, OEE SPLY, OEE YoY Change |
| Downtime | Downtime Hours, Top Downtime Cause, Downtime % Planned |
| Defects | Total Rejected, Top Defect Type |
| Bottleneck | Bottleneck Machine, Bottleneck OEE |

---

## Step 5 — Page 1: Executive Summary

**Visuals:**

1. **KPI cards** (top row) — one card per metric:
   - OEE Weighted — format: `0.0"%"` — conditional colour: green ≥ 85, yellow ≥ 70, red < 70
   - Avg Availability
   - Avg Performance
   - Avg Quality / FPY
   - Scrap Rate
   - Total Downtime Hours

2. **Line chart** — Monthly OEE trend
   - X-axis: `DateTable[Date]` (month granularity)
   - Y-axis: `OEE Weighted`
   - Legend: `kpi_monthly[Machine]`
   - Add a constant line at 85 % (Analytics pane → Constant line)

3. **Card** — Bottleneck Machine + Bottleneck OEE
4. **Slicer** — `kpi_monthly[Machine]` (vertical list)
5. **Slicer** — `DateTable[Year]` (dropdown)

**Formatting tips:**
- Background: white or light grey (#F5F5F5)
- Accent colour: `#4C72B0` (matches Python charts)
- Font: Segoe UI, size 10

---

## Step 6 — Page 2: OEE Detail

**Visuals:**

1. **Clustered bar chart** — OEE components by machine
   - Y-axis: `machine_performance[Machine]`
   - X-axis: `Avg_OEE`, `Avg_Availability`, `Avg_Performance`, `Avg_Quality`
   - Add a reference line at 85 %

2. **Matrix** — Machine performance heatmap
   - Rows: `Machine`
   - Columns: `Year`
   - Values: `Avg_OEE`, `Avg_Availability`, `Avg_Performance`, `Avg_Quality`
   - Conditional formatting on all value columns (Red–Yellow–Green, min 45, max 100)

3. **Line + clustered column** — OEE MoM change
   - Column: `OEE Weighted` (current month)
   - Line: `OEE MoM Change`
   - X-axis: `DateTable[Date]`

4. **Card row** — OEE YTD, OEE Rolling 3M, OEE SPLY, OEE YoY Change

---

## Step 7 — Page 3: Downtime Analysis

**Visuals:**

1. **Bar chart (Pareto)** — Downtime by cause
   - X-axis: `downtime_analysis[Downtime_Reason]`
   - Y-axis: `Downtime Hours`
   - Sort descending
   - Add a line series for cumulative % (calculated column or secondary measure)

2. **Matrix heatmap** — Downtime by machine × cause
   - Rows: `Machine`
   - Columns: `Downtime_Reason`
   - Values: `Downtime Hours`
   - Conditional formatting: white → orange → red

3. **Line chart** — Monthly downtime trend by machine
   - X-axis: `DateTable[Date]`
   - Y-axis: `Downtime Hours`
   - Legend: `kpi_monthly[Machine]`

4. **Slicer** — `kpi_monthly[Machine]`
5. **Drill-through**: set `downtime_analysis[Machine]` as drill-through field
   so right-clicking a machine on any other page navigates here filtered.

---

## Step 8 — Page 4: Defect & Quality

**Visuals:**

1. **Bar chart** — Rejected pieces by defect type
   - X-axis: `defect_analysis[Defect_Type]`
   - Y-axis: `SUM(defect_analysis[Total_Rejected])`
   - Sort descending

2. **Line chart** — Monthly scrap rate trend
   - X-axis: `DateTable[Date]`
   - Y-axis: `Scrap Rate`
   - Legend: `kpi_monthly[Machine]`
   - Constant line at 1 % (world-class target)

3. **Matrix** — Defect occurrences by machine and type
   - Rows: `Machine`
   - Columns: `Defect_Type`
   - Values: `SUM(defect_analysis[Occurrences])`
   - Conditional formatting

4. **Card** — Total Rejected, Top Defect Type

---

## Step 9 — Slicers and cross-filtering

Add to every page:
- **Year slicer** (`DateTable[Year]`) — synced across all pages
  (View → Sync slicers → enable for all pages)
- **Machine slicer** — page-level (not synced, so each page can filter independently)

Enable **cross-filtering** between visuals:
- Format pane → Edit interactions → set all pairs to **Filter** (not Highlight)

---

## Step 10 — Publish and share

1. **File → Save** as `orobic_kpi_dashboard.pbix`
2. For public sharing: **File → Export → Export to PDF** or publish to
   Power BI Service (requires a Power BI account)
3. The `.pbix` file embeds all data — no live connection to CSV files required
   after first load

---

## Data refresh

If you regenerate the CSV files (e.g. after running `generate_dataset.py` and
`etl_pipeline.py` again), refresh in Power BI Desktop:
**Home → Refresh**

The model will re-read all five CSV files and update all visuals automatically.

---

## Notes on planned time

Each row in `kpi_daily` represents **one shift of 8 hours**:
- `Total_Planned [sec]` = 28,800 (constant)
- `Total_Run_Time [sec]` = Planned − Downtime
- OEE = Availability × Performance × Quality / 10,000

This is a **single-shift** model. If the company moves to two shifts, multiply
planned time by 2 and regenerate the dataset with `PLANNED_SEC = 57,600`.
